# Monogram MTProto

A Telegram MTProto client library written in Rust. It gives you a blocking,
handle-based API for sign-in, dialogs, messages, live updates, media transfers,
stickers, instant view, wallpapers, and proxies, with bindings for Kotlin,
Swift, Python, and Ruby generated by
[UniFFI](https://mozilla.github.io/uniffi-rs/latest/). Rust applications can use
the crate directly. It is the engine behind the
[Monogram](https://github.com/monogram-android/monogram) Android client.

- [USAGE.md](USAGE.md): how to call the library, with recipes
- [ARCHITECTURE.md](ARCHITECTURE.md): how it works inside

## Quick start

Kotlin:

```kotlin
val handle: ULong = createEncryptedClient(apiId, apiHash, sessionPath, key32)
connect(handle)

if (!isAuthorized(handle)) {
    val sent = sendAuthCode(handle, phone)
    // show a prompt that matches sent.codeType, then:
    signIn(handle, phone, sent.phoneCodeHash, code)
}

startUpdates(handle)
val chats = getChats(handle)
```

Rust:

```toml
[dependencies]
monogram-mtproto = { path = "../monogram/native/mtproto-rs" }
```

```rust
let handle = monogram_mtproto::create_client(api_id, api_hash, session_path);
monogram_mtproto::connect(handle)?;

// after signing in
let chats = monogram_mtproto::get_chats(handle)?;
let history = monogram_mtproto::get_history_page(handle, chats[0].id, 50, 0, 0, 0)?;
```

Rust uses snake_case names and `u64` handles; generated bindings follow the
target language's conventions. Every call blocks the calling thread, so run
calls on a worker thread. The full walkthrough, including 2FA, updates,
downloads, and error handling, is in [USAGE](USAGE.md#a-complete-session).

## Credentials

1. Create the Telegram account in an official app. The library signs in
   existing accounts only.
2. Get an API ID and hash at [my.telegram.org/apps](https://my.telegram.org/apps).
   One phone number gets one API ID.
3. Pass them to `createClient` or `createEncryptedClient`. Do not commit them.

Sample API IDs from Telegram's open-source clients are rate-limited
(`API_ID_PUBLISHED_FLOOD`) and only suitable for testing. Your app must follow
the [API Terms of Service](https://core.telegram.org/api/terms): it has to say
that it uses the Telegram API and is part of the Telegram ecosystem, its title
must not include "Telegram" unless preceded by "Unofficial", and it must not use
the official logo.

> [!WARNING]
> my.telegram.org can refuse to create an API ID from a VPN, proxy, datacenter,
> or Tor address, usually with a generic form error. There is no client-side
> workaround; retry from a regular connection. See
> [API ID troubleshooting](USAGE.md#api-id-troubleshooting).

## Build

Requirements:

- Rust 1.98 or newer and Cargo
- The runtime checkout `../telers-mtproto-impl`, next to this repository. The
  `vendor/telers-mtproto-impl` submodule is not the build dependency.

```console
git clone --recurse-submodules https://github.com/monogram-android/monogram.git
git clone --recurse-submodules https://github.com/gdlbo/telers-mtproto-impl.git
cd monogram
git submodule update --init --recursive
```

Host build and tests:

```console
cargo build --release --manifest-path native/mtproto-rs/Cargo.toml
cargo test --manifest-path native/mtproto-rs/Cargo.toml
cargo test --manifest-path native/mtproto-transport/Cargo.toml
```

The tests use local sockets and deterministic protocol fixtures. They need no
device, no account, and no connection to Telegram.

The crate is built as a `cdylib` and is not published to crates.io
(`publish = false`), so depend on it by path. It builds for the host and for
Android; other targets need their own build and a transport/TLS review.

### Android

You also need JDK 17, Android SDK 37, and an NDK (CI uses r28c):

```console
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
cargo install cargo-ndk --locked
```

Build the native library and regenerate the Kotlin bindings:

```console
./gradlew :native:mtproto:buildNativeMtproto
```

On Windows use `gradlew.bat`. `-PskipNativeBuild=true` reuses the existing
library and bindings; use it only when both are current, never after a Rust,
protocol, DTO, or schema change.

## Troubleshooting

| Symptom | Check | Details |
| --- | --- | --- |
| Login fails with a generic error | `api_id`/`api_hash`, sample IDs, IP restrictions | [API ID troubleshooting](USAGE.md#api-id-troubleshooting) |
| "No account" for a number | The account must already exist | [Sign-in only](USAGE.md#sign-in-only) |
| No SMS arrives | `codeType`; the code may be in an official app | [No code or no SMS](USAGE.md#no-code-or-no-sms) |
| Code is rejected | Expiry, resend, the `phoneCodeHash` you pass | [Submit the code and password](USAGE.md#submit-the-code-and-password) |
| Session dies right after login | Another client uses the same authorization | [Common errors](USAGE.md#common-errors) |
| Download fails | Media not indexed, `FILE_REFERENCE`, wrong dispatch class | [Download errors](USAGE.md#download-errors) |
| Downloads are slow | Dispatch class, lanes, parts, chunk size | [Tuning downloads](USAGE.md#tuning-downloads) |
| Updates seem to stall | Drain loop running, batches acknowledged | [Live updates](USAGE.md#live-updates) |
| Missing or stale native library | Rebuild without `skipNativeBuild` | [Android](#android) |
| Unfamiliar error | Look it up in the official error database | [Errors](USAGE.md#errors) |
